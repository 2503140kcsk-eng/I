# CFE certificate and hashing format v1

## Status

This is the language-neutral reference contract for certificate v1 and history
ledger v1. Implementations must reject unsupported versions and unknown
required-format fields. The JavaScript reference core is the executable
prototype; Rust/native/WebAssembly implementations must pass the same
canonical vectors before they are considered interoperable.

## Canonical encoding: CFE-CJSON-1

1. Input is JSON only: null, boolean, string, finite number, dense array or
   plain object.
2. Object keys are ordered lexicographically by UTF-16 code units, matching
   ECMAScript string ordering.
3. Strings and keys must contain well-formed Unicode scalar sequences. No
   Unicode normalization is applied: code-point sequences are byte-significant.
4. Arrays preserve order and may not be sparse or have custom properties.
5. Object accessors, symbols, custom prototypes, functions, undefined, BigInt,
   cycles and non-finite numbers are rejected.
6. Negative zero is encoded as zero. Integer-valued numbers outside the exact
   IEEE-754 safe-integer range are rejected.
7. Serialize with ECMAScript-compatible JSON string/number formatting, UTF-8
   encode the resulting string without a BOM, then apply SHA-256.
8. Unknown object fields are rejected by each versioned schema even though
   the general canonicalizer can encode plain JSON objects.

Reference vectors are in spec/canonical-v1-vectors.json.

## Certificate v1 envelope

The top-level object has exactly these keys:

- schema: cfe.shogi.certificate
- version: 1
- objective: tsume-mate
- rulesetId: immutable identifier for the exact rules profile and revision
- verifierAbi: verifier interface/version identifier
- attackerSide: b or w
- root: SHA-256 node ID
- nodes: object keyed by node ID
- provenance: diagnostic metadata; never trusted for validity

A production proof state contains canonical SFEN, absolute turn (b or w),
historyDigest, and the complete replayable historyLedger. Synthetic tests may
use opaque history only when the adapter explicitly opts into
allowOpaqueHistory: true; production builds must never do this.

A proof node has exactly state, kind, and edges. An edge has exactly move and
to.

A node identifier is SHA-256 of the CFE-CJSON-1 encoding of this object:

    {
      schema: "cfe.shogi.proof-node",
      version: 1,
      rulesetId,
      attackerSide,
      state,
      kind,
      edges: sorted-by-USI-move(edges)
    }

The root identifier commits to the root state and, recursively through
content-addressed child IDs, the entire reachable DAG. The verifier also
rejects unreachable extra nodes, cycles and duplicate move labels.

## AND/OR proof semantics

Let A be attackerSide. A state is an attacker node iff its side-to-move is A.

- OR: attacker to move, ongoing position, and at least one certified legal
  checking move. Every listed edge must be a legal checking move. One
  successful attacker continuation is sufficient.
- AND: defender to move, ongoing position, and the edge set must equal the
  complete set of legal evasions independently regenerated by the verifier.
  Every evasion must lead to a recursively verified proof.
- TERMINAL_MATE: defender to move, independent terminalStatus must say
  checkmate, and there are no outgoing edges.
- Repetition, perpetual-check loss, impasse, non-mate terminal positions,
  unknown states and timeouts are not mate leaves under this objective.
- The root must be bound to the caller's expectedRootState; a certificate
  without that external binding is rejected.

The verifier must replay history with the exact selected rules profile,
independently generate all legal evasions, and independently apply every edge.
The search engine's proof numbers, PV, hash table, NNUE or neural scores are
not part of the trusted base.

## History ledger v1

Top-level exact keys:
schema, version, rulesetId, initialSfen, events, digest.

Each event has exact keys:
ply, mover, move, gaveCheck, resultingSfen.

The digest starts at SHA-256 of the CFE-CJSON-1 encoding of:

    {
      schema: "cfe.shogi.history-ledger",
      version: 1,
      kind: "genesis",
      rulesetId,
      initialSfen
    }

For each event, the new digest is SHA-256 of the CFE-CJSON-1 encoding of:

    {
      schema: "cfe.shogi.history-ledger",
      version: 1,
      kind: "event",
      rulesetId,
      previousDigest,
      event: { ply, mover, move, gaveCheck, resultingSfen }
    }

This hash chain detects tampering; it does not prove move legality. The
production rules adapter must replay every move, recompute each resulting
position and check annotation, and adjudicate repetition/perpetual check.

## Footprints

A footprint is a retrieval index, not proof. Cube literals are flat
feature-equality predicates. LEFT_STRONGER means every assignment satisfying
the left cube also satisfies the right cube. DISJOINT means a shared feature
has conflicting values. Any exact or abstract hit only identifies a
certificate candidate. Proof transfer remains forbidden until a separately
specified and machine-checked parametric proof establishes that changing the
omitted state features preserves every legal-move and history precondition.
